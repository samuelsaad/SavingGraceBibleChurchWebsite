# Existing SermonAudio transcript retrieval (D-174)

This task retrieves existing complete original-language transcripts only. It is
not generation, transcript creation, enrichment, approval, import or publication.
The authoritative WordPress source is read-only. Existing application databases,
frontends, staging and running services are untouched.

## Source and scope

Include published and titled pending Advanced Sermons records without a valid
YouTube mapping, including validated inert video-embed references. Require one
explicit SermonAudio recording ID joined through WordPress identity. Independently
verify official broadcaster `savinggrace`, church name and Westmeadows address.
Require recording identity, title, actual preached date and available speaker
corroboration. Copied, duplicate, conflicting and missing evidence stays unresolved.
Never match on fuzzy title alone, upload date or a typical speaker.

A live source refresh must fail if its account has broader privileges than the
approved read-only grant set. Do not weaken that guard or query with those powers.
The separately selectable `--retained-evidence <private-evidence-directory>` path
may instead use already captured source metadata/export and its exact hashes,
timestamps and recorded freshness limitation. It makes no production connection
and cannot establish current WordPress changes or exhaustive live coverage.
Current official recording checks remain mandatory; conflicting evidence is held.

Freeze the complete verified inventory and its SHA-256 in ignored private storage.
This is not a fixed 36-record run and no expired batch exception applies. Exclude
and reuse successfully retrieved sources by receipt, exact identities and hash.

The verified 119-target frozen inventory SHA-256 is
`a4fa3627682043c4b06aa65ddbebdab75f1fc29aec93e2d250bda537d9b0cd2b`.
Of 464 retained WordPress sources, 332 have valid YouTube mappings, three are

This is a retained-source inventory, not a claim of a successful fresh live query.

## Official read-only API contract

Inspect https://api.sermonaudio.com/v2/docs and its advertised OpenAPI specification.
The documented authentication header is `X-Api-Key`. Use only GET broadcaster
information and GET sermon information. `Sermon.transcript` is `TranscriptMedia`:
language, downloadURL, approveTimestamp and autoGenerated. Follow the returned
original-language downloadURL, never guessed endpoints, snippets, summaries or
translations. The observed official download host is `cloud.sermonaudio.com` and
the source path ends in `.transcript`. Reject other origins, media paths, embedded
credentials and translated URLs; never forward the API key to the download host.

There is no transcript-creation or audio-processing request. Provider approval
timestamps and auto-generation labels are provenance, not local human approvals.
Store exact source bytes separately from any future prepared transcript. Retain
source identities, language, URL, retrieval time, metadata/source-version fields,
byte/word counts and SHA-256; independently reread saved bytes. Missing version
fields remain unavailable, not invented. Reject HTML/login/error/binary responses.

Read the key only from protected owner-local storage outside all repositories and
build contexts. Never print it or place it in arguments, logs, frontend or Git.
Private transcript text may enter necessary primary Codex verification results,
but not ordinary logs, messages, reports, screenshots, fixtures or tracked files.

## Recovery and bounds

One serial worker, exclusive lock, one-second minimum request spacing. Honour
Retry-After; at most three attempts for transport failures, 429 and temporary 5xx.
Do not retry 401/403 or mutate credentials. Delays over 60 seconds checkpoint and
stop; no background automation. Immutable source/metadata/receipt artifacts and
atomic integrity-bound checkpoint replacement preserve previous attempts. Never
overwrite a conflicting source or reset history. Resume the exact frozen inventory.
Identical verification/reruns reuse successful bytes without another download.

Commands after locked dependency installation:

```text
node --import tsx src/sermonaudio/transcript-cli.ts inventory
node --import tsx src/sermonaudio/transcript-cli.ts retrieve
node --import tsx src/sermonaudio/transcript-cli.ts verify
```

First verified download is the supported-method test; continue through the same
inventory automatically. Record individual unavailability/conflicts and continue
independent targets. Systemic authentication/identity failures stop safely.
Relevant anonymized tests, type checks, build and outgoing credential/private-file
scans precede safe local commits. No database tests or migrations are needed for
this source-only implementation; no database write is authorized by D-174.
