# Advanced Sermons Migration Contract

**Version:** 1.2
**Status:** Phase 3B.2 three-caption private rehearsal implemented; not approved for production execution or the remaining 450 sermons

## 1. Source boundary

The canonical source collection is `wp_posts` where `post_type = 'sermons'`, joined only to its WordPress postmeta, taxonomy, termmeta, and approved attachment rows. The `wp_sb_*` tables and every other sermon-like post type are out of scope.

The importer consumes structured records supplied through an approved read-only extractor. It does not hold MariaDB credentials, execute WordPress/PHP code, or mutate WordPress.

## 2. Inclusion contract

| Source condition | Result | Target visibility | Audit reason |
| --- | --- | --- | --- |
| `post_status = 'publish'` | Include | `published` | `included_published` |
| `post_status = 'pending'` and trimmed title is nonempty | Include | `pending`/unpublished | `included_titled_pending` |
| `post_status = 'pending'` and trimmed title is empty | Exclude | None | `excluded_blank_pending_title` |
| `post_status = 'draft'` | Exclude | None | `excluded_draft` |
| Any non-`sermons` post type | Exclude | None | `excluded_legacy_post_type` |
| Any `wp_sb_*` record | Exclude | None | `excluded_legacy_table` |
| Unknown Advanced Sermons status | Reject for review | None | `unsupported_source_status` |

Current expected result: 453 included (448 published, 5 pending), 3 Advanced Sermons drafts excluded, 0 blank pending excluded, and the separately documented legacy tables/12 legacy post-type records ignored.

## 3. Identity, timestamps, and dates

- Target UUIDs are deterministic UUIDv5 values derived from source system, source entity type, and WordPress source ID.
- `migration_records` has a unique `(source_system, source_entity_type, source_id)` key.
- Preserve source ID, local/GMT create timestamps, modified timestamps, legacy path, and deterministic source checksum.
- `service_date` equals the exact local calendar date of WordPress `post_date`.
- A non-Sunday `service_date` is imported unchanged and emits `non_sunday_service_date`.
- Current expected warning count is four included sermons.

## 4. Slugs and visibility

- Preserve nonempty published/pending WordPress slugs after safe canonical validation.
- Enforce a stable, case-insensitive unique canonical slug.
- A missing/invalid/colliding included slug emits a blocking migration error unless an explicit deterministic override map exists.
- Public repositories return `published` only. Pending records are available only to authorised admin operations.
- Excluded source records create audit/exclusion results but no sermon row or public redirect.

## 5. Relationships

- Every sermon has one runtime speaker through nullable `sermons.speaker_id`; null is allowed only while an imported/draft record is incomplete.
- If source input contains more than one speaker, emit `multiple_source_speakers` at error severity, preserve warning/audit evidence, import no speaker for that record, and never choose one silently.
- Migration `0004` refuses former local join conversion and reports all affected sermon UUIDs if any sermon has more than one speaker. Series remains many-to-many with deterministic order.
- Books remain source classifications with an optional canonical Bible-book mapping.
- Preserve source term/taxonomy IDs, names, slugs, and relationship provenance.
- Do not merge near-duplicate or misclassified terms without an approved mapping file.
- Do not create campus/service-type entities from the current source because no live term/relationship exists.

## 6. Scripture

Each untouched source value becomes a `scripture_reference_sources` row:

- `source_kind = 'postmeta'` for `asp_sermon_bible_passage`;
- `source_kind = 'taxonomy'` for `sermon_topics` terms;
- original value and source IDs are immutable audit fields.

`scripture_references` stores the target display value and optional structured book/chapter/verse data. It may link to one or more source rows. Exact normalisation is allowed only when reversible; otherwise retain separate references and emit:

- `scripture_source_conflict` for the 36 published both-present mismatches;
- `scripture_single_source` for the 13 published meta-only/taxonomy-only rows;
- `scripture_parse_incomplete` when structured parsing is unsafe.

## 7. Media and resources

- YouTube: accept approved YouTube URL forms, extract a valid provider ID, store a canonical HTTPS URL, and retain the original source value only in controlled migration audit input.
- SermonAudio: parse known iframe `src` values as inert text, validate the HTTPS provider host/path, and store provider-specific ID/URL fields.
- Never store imported embed HTML in a public/renderable API field.
- API responses expose controlled media descriptors; UI embed markup is generated by the application with an explicit accessible title.
- A sermon may contain both providers or either provider independently.
- PDF, bulletin, featured image, body, and resources are nullable; no empty placeholder rows are created. `summary` may be null only while a record is incomplete and is never fabricated or automatically approved.
- Unsupported or malformed media emits a warning/error and is never rendered directly.

## 8. Transcript, Q&A, and historical enrichment

- Each included historical record requires a nonblank approved 80-2,000 character sermon description, a nonblank `approved` full transcript, and 5–10 nonblank, consecutively ordered, all-`approved` Q&A pairs before launch, including the five pending/non-public records.
- Existing nonblank source summaries are preserved as `draft` with imported provenance. Fixture/import reruns may fill only a missing description and must never overwrite an approved description.
- New records may be saved incomplete as drafts but cannot schedule or publish until they also have one speaker, required metadata, and valid controlled media.
- Transcript/Q&A fields accept plain text only. Status, non-secret provenance, created/updated/reviewed/approved timestamps, reviewer/approver, audit history, and optimistic concurrency are preserved.
- Draft enrichment bundles are strict schema-versioned JSON keyed by source WordPress ID, target UUID, and expected row version. Queue records are deterministically sorted by source ID and need code.
- Local draft imports are transactionally idempotent by SHA-256 receipt; the same bundle is unchanged on rerun, a changed stale bundle is rejected, and imported content is always `draft` with a `human_approval_required` warning.
- No provider, media service, AI API, WordPress, or production database may be contacted by this local workflow. Provider interfaces do not constitute an implementation or approval.
- Phase 3B.2 bundle schema version 3 adds private, structured YouTube Studio export provenance and safe warning codes. Operational timestamps and expected row versions are excluded from the content checksum so an identical regenerated bundle remains idempotent.
- A differing draft import must refuse to overwrite any approved description, approved transcript, or approved Q&A content. Identical approved content is preserved rather than downgraded.
- Caption preparation is local-file-only and verifies that the retained case-insensitive word sequence is unchanged. Insufficient sentence boundaries produce `manual_punctuation_required` and no derived outputs.
- Local pilot rows use `source_system = 'phase3b2_pilot'`; historical readiness continues to count only approved `wordpress` migration records.

## 9. Search and API contract

- PostgreSQL full-text search covers published title (A), sole speaker/series/scripture/book terms (B), approved sermon description (C), and body plus approved transcript/Q&A (D). Draft/in-review/missing descriptions and enrichment never enter the public search vector.
- Legacy keyword behavior is WordPress native title/content/excerpt search plus exact taxonomy-name matching; target weighted ranking is a documented improvement rather than claimed byte-for-byte ranking parity.
- GIN indexes support the search vector; B-tree indexes support status/date/slug and join filters.
- Structured filters use exact source-compatible slugs for speaker, series, passage, and book.
- Cross-dimension filters combine with AND. Do not reproduce the installed parent's contradictory AJAX-prepared OR branch.
- `sermon_dates=YYYY-MM-DD - YYYY-MM-DD` translates to inclusive `dateFrom`/`dateTo` against exact `service_date`; malformed or reversed values are rejected at the compatibility boundary.
- Anonymous results are paginated, deterministically sorted, length-limited, and cannot reveal pending content through results or counts.
- API v1 preserves legacy-compatible query translation at the web boundary without exposing raw migration metadata.

## 10. Audit and warning output

Every processed source record returns a structured result containing source type/ID/status, outcome, target ID when included, safe reason code, and warnings. It must not contain credentials, licence values, raw embed HTML, password hashes, auth/session data, or unrelated personal information.

Legacy `post_views_count` is retained only in `sermon_legacy_metrics`/private source-audit output. It is never part of `ImportedSermon`, public repository projection, or API response.

Required outcome categories: `included`, `excluded`, `rejected`. Required warning fields: code, severity, source entity type/ID, field, and safe detail. Output ordering is deterministic by source type then numeric/string source ID.

## 11. Idempotency and dry run

- Dry run performs validation and transformation and produces the complete report without target writes.
- Reprocessing identical input yields identical target IDs, checksums, transformations, warnings, and ordering.
- A future load uses upserts keyed by source identity and a migration-run transaction; that path is not authorised against production in this milestone.

## 12. Permanent whole-site SEO migration gate

This sermon migration contract is a subset of the permanent whole-site SEO contract in `seo-migration-validation-plan.md`. It does not by itself establish launch readiness.

- Preserve every proven indexable sermon archive, detail, taxonomy/filter landing, and pagination URL wherever practical. Any unavoidable change requires an identity-matched, one-hop permanent `301` in the reviewed whole-site URL manifest.
- Preserve established titles, descriptions, headings, visible content, dates, internal links, image alt text, social metadata, and other search signals. An empty current AIOSEO override is not permission to discard template-generated or visible metadata.
- Keep public sermon pages server-rendered, self-canonical, crawlable without JavaScript, correctly status-coded, and reachable through crawlable internal links and XML sitemaps.
- Exclude pending, draft, scheduled, unpublished, archived, admin, search-result, and preview routes from public sitemaps and indexability.
- Correct the observed staging-origin social image before launch and prevent non-production origins from appearing in production canonicals, metadata, structured data, or sitemaps.
- Reconcile the 448 verified published sermon detail paths, `/sermons/`, and all 50 verified archive pages into the future whole-site one-to-one URL inventory. Do not infer the rest of the site from this sermon subset.
- A fresh public-site crawl or church-owned Search Console/analytics export remains a later, separately approved read-only discovery task. No production contact is authorised by this contract.
- Production launch remains blocked until the complete whole-site SEO acceptance artifacts pass; ranking improvement is not guaranteed.
- The complete approved description is rendered uncollapsed in initial server HTML below title/core metadata and before media, transcript and Q&A. Approved transcript and Q&A are also rendered initially; transcript alone uses collapsed native `<details>`. List responses may include approved bounded descriptions but never duplicate transcript/Q&A bodies, and FAQ schema is not added automatically.
- A previously published sermon slug change transactionally creates or updates a direct `301` from the former path and collapses earlier aliases to the final canonical target.
- Safeguarded permanent deletion is a target-administration operation, never a source-migration cleanup. It may run only from `archived` and requires confirmation, row version, reason, a minimal non-content tombstone, and either a validated redirect or explicit gone disposition for any formerly public URL. It never changes or deletes the WordPress source row.

## 13. Acceptance invariants

- Exactly the approved records are included/excluded.
- All included source identities and timestamps remain traceable.
- Four current included non-Sunday dates remain unchanged and warned.
- Nine current multi-series assignments survive.
- Every normal source record retains its sole speaker; any multi-speaker anomaly remains incomplete and explicitly warned rather than silently resolved.
- The historical launch command fails unless included records, sole speakers, approved descriptions, approved transcripts, valid 5–10-Q&A records, valid controlled media, and complete records are all exactly 453 and incomplete is zero.
- All 453 real historical description/transcript/Q&A sets remain outstanding until a separately authorised production/review milestone completes them.

Migration `0005_approved_sermon_descriptions.sql` reuses `summary`, adds constrained description lifecycle/provenance/review columns plus controlled `seo_description`, rebuilds approved-only weight-C search, and extends readiness/backfill. Its down migration removes every `0005` constraint and column, restores the `0004` search/readiness contract, and supports clean reapplication without content loss or silent approval.
- The 36 conflict and 13 one-source-only published scripture cases remain reviewable.
- No raw imported embed HTML is emitted by public/admin API contracts.
- Drafts, blank pending records, legacy tables, and other sermon post types never enter target sermon collections.
- Rerunning a dry run produces byte-equivalent canonical JSON after excluding the run timestamp.
- Every included public sermon has a reviewed whole-site SEO URL disposition and passes the permanent non-regression gates before production cutover.
