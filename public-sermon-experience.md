# Public Sermon Experience

**Status:** Local implementation only; not deployed or production-authorized

**Data boundary:** Published sermons and independently approved enrichment projections from PostgreSQL

## Public route contract

The local loopback application serves:

- `/` — the church homepage: welcome card, Lord's Day services, the four pillars, the newest sermons, About us, the offering panel, upcoming events and the contact footer.
- `/sermons/` — published sermon archive, search, filters, and page one (SermonsV2 in the menu).
- `/sermons/page/{n}/` — stable server-rendered archive pagination.
- `/sermons-v1/` and `/sermons-v4/` (with `/sermons-v4/page/{n}/`) — the alternate SermonsV1 and SermonsV4 presentations: non-indexable comparison surfaces whose canonical is the archive.
- `/brand/saving-grace-logo.png` — the church's own logo, served from embedded bytes by every runtime and by the static build.
- `/sermons/{slug}/` — published sermon detail with independently gated enrichment and metadata-related sermons.
- `/sitemap-sermons.xml` — sermon-only sitemap containing the archive and published detail URLs.
- `/api/v1/sermons` and `/api/v1/sermons/{slug}` — the existing bounded public JSON contract.

Requests without the canonical trailing slash receive one direct `301`. Search and arbitrary filter combinations are functional but `noindex, follow`; unfiltered archive pages use self-canonicals. Dedicated indexable speaker, series, book, and passage landing pages are deliberately not invented while the production canonical/indexability allowlist remains unresolved. Their current stable public interface is the archive query contract.

The static Astro production adapter remains undecided. These local routes are framework-independent server handlers exercised through the existing loopback Node/PostgreSQL harness; they do not select a production runtime.

## Presentation layer

The sermon frontend is a framework-independent presentation package under `src/frontend/`. It contains no database or Node-only code, so the server handlers and the static Astro pages consume the same modules:

- `tokens.ts` — the only source of colour, type, spacing, radius, elevation, motion and measure values, emitted once as custom properties. The contrast test computes every text/surface, spine-lettering and control pairing from these tokens.
- `html.ts` — an escaping `html` tagged template. Every interpolation is escaped unless it is already-rendered markup, so approved content, slugs and query values never reach a template unescaped.
- `routes.ts` — route paths, legacy-compatible query builders (`withFilter`, `withoutPassage`, pagination) and query-state predicates. Nothing here changes a URL shape.
- `canon.ts` — pure helpers for the Canon: shelf geometry for the 66 books, the 1,189-chapter canon strip, per-book counts and chapter/verse availability derived from repository projections, reading statistics and the short card excerpt.
- `assets/logo.ts` and `content/home-content.ts` — the church's logo as embedded bytes with its provenance, and the homepage's verbatim text with the registry of pending labels.
- `styles/` — readable CSS partials (`core`, `shelf`, `sermon`, `cards`, `v4`, `home`, `preview`) compacted at module load. A page inlines only the blocks it uses; boundary and index pages carry no shelf, card or player CSS, and the `preview` block never enters the static build.
- `scripts/` — two readable enhancement scripts (`canon`, `sermon`). Each is embedded as a `<script>` body and hashed into the Content-Security-Policy from the rendered document, so the header and the markup cannot disagree.
- `components/` — the shelf, legend, canon strip, book tab and open book (`shelf.ts`); one catalogue entry with card, row and related variants plus name indexes and chips (`catalogue.ts`); the V4 card and card grid (`cards.ts`); the finder, filter tokens and masthead search (`search.ts`); section furniture, title pages and pagination (`sections.ts`); controlled media (`media.ts`); the bookshelf mark and boundary art (`marks.ts`); the homepage and footer glyphs (`glyphs.ts`).
- `pages/` — the composers for the church homepage (`home.ts`), the SermonsV1 landing page (`sermons-v1.ts`), the SermonsV2 archive (`archive.ts`), SermonsV4 (`sermons-v4.ts`), the sermon, taxonomy and boundary pages.
- `shell.ts` — the document skeleton, the optional notice band, the masthead (the church logo, About Us, the Sermons link or menu, News & Events, Contact Us, the compact search and the Give button), the footer with the canon strip, the contact, get-involved, recent-sermon and services columns, the bottom bar and the imprint, the preview band and the inline favicon.

`src/server/http/public-sermon-page.ts` is the public router only (routes, redirects, sitemap, error mapping) and re-exports the render functions for existing callers; `alternate-archives.ts` serves `/sermons-v1/` and `/sermons-v4/` for the same repository and context, and `site-assets.ts` serves the allowlisted logo. `frontend-archive-loader.ts` is the single place that decides when discovery sections load, and `frontend-response.ts` derives every response's policy from the document it sends: hashed `script-src` and `style-src` (no `unsafe-inline`), and `frame-src https://www.youtube-nocookie.com` only when the page contains real click-to-load plate markup.

The concept is **the Canon**: every sermon is shelved under the Bible book it was preached from. The landing page and the archive open on a bookshelf of all 66 books in canonical order, each spine as wide as the square root of its chapter count and coloured by its literary group; books with sermons are filled cloth spines carrying a count sticker and are links, books without sermons are outlines and are not. A to-scale canon strip (one unit per chapter) runs through the footer, sermon heads and taxonomy pages so a visitor always sees where the archive's sermons sit within Scripture. Taking a book off the shelf opens it: a book tab, then chapter and verse rulers whose every cell is a server search. Type is set in system fonts only, light-only, with a display serif for titles, a text serif for reading, a condensed signage face for the shelf, eyebrows and counts, and a sans for controls. The bookshelf mark, its favicon and the boundary art are this website's own device, stated in the footer as such; there is no photography, slogan, invented ministry or contact detail. The site honours reduced-motion and forced-colours preferences and prints without navigation chrome.

## Authenticated local frontend preview

The local loopback harness also provides `/frontend-preview/`, archive/detail pages and preview-only speaker, series and Bible-book taxonomy pages. These pages reuse the same rendering components as the public experience, but the selector is limited to the exact completed three-pilot/12-Wave-1 source scope and independently requires private draft lifecycle, completed guided review, approved current description/transcript/Q&A, controlled media, a reviewed primary-passage outcome, and non-superseded provenance. In accordance with D-141, an explicit no-primary outcome is complete without inventing a Bible-book classification; the preview alone labels that outcome as "No single primary passage (reviewed outcome)", and public pages render nothing for it.

The dashboard obtains a short-lived in-memory preview session through the existing local administrator identity. The session cookie is `HttpOnly` and `SameSite=Strict`; a copied URL, preview query parameter or identity header is insufficient. Every preview response is private/no-store and `noindex, nofollow, noarchive`, omits canonical/Open Graph metadata, and has no sitemap, feed or structured-data endpoint. The dashboard link is injected only by the loopback runtime, so neither it nor private preview wiring enters the static production build.

The masthead carries the church logo as the home link, then About Us, the Sermons item, News & Events and Contact Us, the compact search and a Give button; About Us, News & Events, Contact Us and Give point at the homepage's own sections. On public pages the Sermons item is a plain link to the archive; in the authenticated preview and the sealed visitor runtime it is the native details menu listing SermonsV1, SermonsV2, SermonsV4, Speakers, Series and Books, with `aria-current="page"` on the current entry. On narrow screens the search becomes a **Search** link to the archive's search field. The Books index renders the full shelf followed by a text table of all 66 books with group, chapter count and sermon count; a book page opens that book with its chapter ruler and lists its sermons.

## Search and filters

Search uses the existing generated PostgreSQL search vector and GIN index. An explicit match-priority tier orders whole-query matches as title first, Scripture reference or approved Bible book second, series or speaker third, approved description fourth, and body/approved transcript/approved Q&A fallback last. Within that tier, PostgreSQL’s vector weights are:

1. Title — weight A.
2. Speaker, series, Scripture, and Bible-book search terms — weight B.
3. Approved sermon description — weight C.
4. Published body plus approved transcript and approved Q&A text — weight D.

Vector rank is descending within the match-priority tier, followed by requested service-date order and stable sermon ID. The title also has a parameterized escaped partial-match fallback. Search input is trimmed, bounded to 120 characters, and punctuation-only input becomes an ordinary browse rather than a database search.

The **finder** is one row: Search sermons, Speaker, Series and a Search button; speaker and series options show their sermon counts when the projection carries them. Beneath it a native **More filters** disclosure holds the broad Bible-book select (hidden while a passage is in scope), the legacy Scripture-reference select, the sort order and the inclusive service-date bounds; it opens server-side whenever one of those filters is active and its summary shows a visible "N filters active" badge. Passage state rides along in hidden inputs so a keyword search keeps the open book. The form submits to `…/sermons/#results`, so a completed search lands on the results section without JavaScript; the `canon` enhancement additionally moves focus to that section, whose accessible name combines the results heading and the count, restores the disclosure on browser back/forward, and leaves empty or default fields out of the submitted URL. Every active filter is shown as a removable token that drops only that parameter, with **Clear all** returning to the plain archive.

The Bible passage flow is the shelf and the open book, backed by `passageBook`, `passageChapter`, `passageVerse` and an explicit `passageScope`; the server contract still accepts the legacy optional `passageEndVerse`. Every spine, chapter cell, verse cell and **Search all of …** control is an ordinary link that performs that search on the server, so without JavaScript a single activation of a book searches the whole book and reveals its chapters, a chapter searches that chapter and reveals its verses, and a verse searches that exact verse. Filled cells mark chapters and verses covered by confirmed single-chapter primary passages, and any cell can be searched. With the enhancement each grid is one Tab stop with arrow-key, Home and End movement, Space activation and Escape to the grid's skip link; the skip links themselves remain ordinary Tab stops. **Put the book back** clears the passage and returns to the results.

Book-only, whole-chapter, exact-verse and legacy verse-range requests use inclusive interval overlap against only administrator-confirmed `primary` relationships. Supporting, unclassified, pending, rejected and private relationships never satisfy this filter. A keyword and primary-passage request combines with `AND`; the results title and the filter tokens name both dimensions. Broad Bible-book and precise-passage state is synchronized so the form cannot submit contradictory books, while unrelated filters and pagination/history state are preserved. Scripture-shaped keyword input such as `Romans 8` remains ordinary PostgreSQL keyword/structured Scripture search; the open book neither runs semantic search nor changes metadata-related recommendations.

## Archive discovery modes

The unfiltered first archive page is the discovery view: a title page with the library summary (sermons, books of 66, speakers, series), the finder, **By Bible book** as the full shelf, **Latest sermons** as exactly the three most recent eligible sermons in deterministic service-date/ID order rendered as cards led by their book tab, **Browse all N sermons, newest first**, and **By speaker** and **By series** as chips with counts. **Browse all** enters the URL-addressable `?view=recent` nine-item newest-first list with continuous ordinals, numbered pages, Previous/Next and **Back to the shelf**. Each catalogue entry leads with the reviewed passage as a signage stamp (omitted when the title itself already states that reference), then the title as the single link with a hit area covering the whole entry, then date, speaker and series, then the approved description clamped to three lines in rows (four on mobile) with the full text left in the DOM.

Any search or filter state switches to the results view: a title page whose eyebrow and title name what was asked for ("Sermons by …", "Sermons in the series …", "Preached from …", "Results for …", or the combined dimensions joined by middle dots), the finder with its tokens, the open book whenever a book is in scope (otherwise the shelf folded into a **Choose a Bible book** disclosure), then the numbered results with their count and pagination. Expanded and result modes hide the discovery sections.

**Topical sermons** is a section boundary that renders only when the repository returns administrator-approved topical sermons. The current schema has no such lifecycle, so the section is absent; a missing primary passage is never inferred to mean topical, and a series literally named "Topical" is simply a series.

Series and speakers are typographic indexes with counts on the landing page and chips with counts in the archive; there are no carousels. Matching items and detail pages label reviewed coordinates as "Preached from". Historic unreviewed Scripture metadata is not shown on visitor-facing pages; it continues to power the existing keyword/structured Scripture path where already approved. The passage filter does not query title text, run an embedding model, read semantic relationships or alter metadata-related sermon scoring.

## SermonsV4

SermonsV4 at `/sermons-v4/` combines the complete SermonsV2 opening section (eyebrow, title, library summary and the whole finder, retargeted so searches, tokens, the open book and pagination stay inside V4 under `#v4-results`), the unchanged 66-book shelf folded behind a native "Browse by Bible book" disclosure that is closed on first load and shows a compact canon strip and count in its summary, and an equal-size card grid whose first card is the latest sermon. Every card is the same anatomy and size: a cloth-hued plate lettered with the literary group, the book and the reference and finished with a to-scale "you are here" strip of the canon stands in for the image slot; then date and series, the title as the single link whose hit area covers the card, speaker and passages, a short server-side excerpt, and a footer with the book link. The latest sermon is identified by position, a gilt bookmark ribbon and a gilt frame and is never repeated; result pages show continuous ordinals in the plate corner instead. Topical sermons take the plum plate; an unclassified sermon takes a neutral plate with the shelf mark and the words "Not yet shelved". Three columns at desktop, two on tablets and one on phones; hover lifts the card, focus draws the ring on the card, forced colours and print keep borders and hide the plate texture. SermonsV1 keeps its exact presentation at `/sermons-v1/`; SermonsV2 is unchanged at `/sermons/`.

## Interim metadata-related sermon scoring

Related results are deterministic and explainable. Each published candidate receives:

- 100 points when it shares at least one series.
- 70 points when it has an exact normalized Scripture display match or an overlapping structured chapter range in the same canonical Bible book.
- 35 points when both sermons have an approved classification for the same canonical Bible book.
- 15 points when it has the same speaker.

Candidates are ordered by total score descending, service date descending, then stable sermon ID. The current sermon is excluded, each candidate is selected once, unpublished/deleted candidates are excluded, zero-score candidates are omitted, and the result is limited to three sermons. The page shows the matching reason categories without exposing internal numeric scores.

The current schema has no manually curated related-sermon override and no approved-topic lifecycle suitable for recommendations. This implementation does not invent either one and does not use unreviewed source topic terms as theological classifications. A future curated override would require a separately approved schema and review contract.

This interim baseline is metadata-based; it is not description-based semantic similarity and must not be labelled **Related themes**. A future **Related themes** feature is explicitly deferred. If separately authorised, that score must use approved public sermon descriptions only: Scripture, title, series, speaker, topics and every other metadata field must not influence it. Scripture-based recommendations may remain separate and clearly labelled, for example **More on this passage**.

The offline description-semantic foundation now has a verified external local model and locked server-only adapter alongside the separate persistence contract, exact float32 mechanics, shared approval/publication eligibility and stale-data removal. Only synthetic inference has run: no real description has been embedded, no build has passed human quality review, and semantic results are not wired to this public page or API. Missing or pending semantic data therefore produces no **Related themes** heading. See `description-related-themes-foundation.md`.

## Publication and privacy enforcement

- Public list, detail, filter-option, sitemap, related-sermon, and redirect-target queries share one strict selector requiring `status = 'published'`, no deletion, complete readiness, a reviewed primary-passage outcome, approved current description/transcript/Q&A, controlled media and no superseded generation provenance.
- A published lifecycle flag alone is therefore insufficient to expose a sermon.
- Heavy transcript and Q&A bodies remain absent from archive/list responses.
- Missing enrichment omits its heading and section; it does not render a misleading placeholder.
- Search refresh documents include only approved description, transcript, and Q&A text.
- Filter options derive from published relationships, not stored legacy term counts.
- Sitemap entries derive from published sermons only.
- Redirects are served only from stored internal mappings: a direct `301` must target a currently published canonical sermon, while an authenticated gone disposition returns `410`. Unknown/private slugs return the same controlled `404`.
- Public routes never expose administrator preview functionality, migration provenance, legacy metrics, raw embeds, credentials, or raw database errors.

## Rendering, SEO, and accessibility

Archive and detail content is present in initial server HTML and does not require JavaScript. The sermon page is a reading room: the classified book's tab at the left (a link to that book's whole-book search, with its count), then the canon strip marking the book, the trail, the passage stamp, the title and the date/speaker/series line; the approved description; **Watch**, a click-to-load plate; **Transcript**; **Questions for reflection**; then metadata-related sermons. An **On this page** rail lists the sections present, marks the visible section as `aria-current="location"` with the enhancement, and moves above the article on narrow screens. The approved description is visible before media, transcript and Q&A. The transcript is a native `<details>` that is open by default, shows its word count and reading time, numbers its paragraphs in the margin on wide screens, keeps the complete approved text in the initial HTML and opens for printing; every Q&A pair is rendered open in normal flow, as `AGENTS.md` §11 requires, and no FAQ structured data is emitted. A valid controlled YouTube player is click-to-load, uses the privacy-enhanced host, never autoplays and makes no provider request until the visitor explicitly chooses to load it; the consent copy names youtube-nocookie.com, the loading state is announced, focus moves to the player, and the page never links to a website-owned YouTube URL.

Pages provide stable canonicals, controlled title/description and Open Graph metadata, correct `404`/`410` behavior, a published-only sermon sitemap, labelled filters, one page-level `h1`, header/navigation/search/main/footer landmarks, keyboard-visible focus, 44-pixel targets for standalone controls and ruler cells, list semantics preserved where list styling is removed, a skip link and shelf/ruler skip links, useful empty/error/404 states with the site navigation intact, responsive layouts verified at 1440, 768, 375 and a 720-pixel 200%-zoom-equivalent width without horizontal overflow, a long-transcript reading measure, and reduced-motion, forced-colours (outlined spines, tabs and rulers) and print handling. Automated checks are structural; no formal WCAG conformance is claimed.

This sermon-only implementation does not satisfy the permanent whole-site SEO launch gate. Production still requires the authenticated whole-site URL manifest, canonical-host decision, crawl/parity evidence, approved performance thresholds, production runtime, protected identity, and explicit deployment authorization.
